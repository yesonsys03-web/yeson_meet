# 설치 가이드 — yeson-meet (미서명 배포)

> **대상:** 직접 자가호스팅하는 일반 사용자. 이 문서는 두 앱을 **코드서명 없이** 배포할 때 각 OS가 띄우는 "확인되지 않은 개발자" 경고를 **안전하게 통과**하는 방법을 안내합니다.
> **왜 미서명인가:** 사내 LAN 운영 단계에서는 Apple 공증/Windows Authenticode 인증서를 구매하지 않습니다(턴키 계획 §10). 대신 OS별 1~2클릭 안내로 설치합니다. 배포 규모가 커지면 macOS는 Apple 공증이 유일한 진짜 해결책이며, 그때 P9(서명 엔지니어링)로 승격합니다.

---

## 0. 두 개의 앱과 설치 순서

yeson-meet는 **앱 2개**로 나뉩니다(자가호스팅, SaaS 아님):

| 앱 | 패키지명 | 누가 설치 | 역할 |
|----|----------|-----------|------|
| **서버 콘솔** | `yeson-server-console` | 운영자(서버 PC 1대) | 번들 서버(FastAPI+SQLite) 실행·감독, 공개 터널/QR |
| **클라이언트** | `yeson-meet`(데스크톱) | 회의 캡처 PC | 회의 오디오 캡처 → 서버로 전송, 자막 표시 |

**권장 설치 순서**
1. **서버 콘솔**을 서버 PC에 설치 → 첫 실행 → 운영자 계정 생성 → **Start**.
2. 서버 콘솔에서 **디바이스 키 발급**(콘솔 내 발급 UI).
3. **클라이언트**를 회의 PC에 설치 → 서버 주소 + 디바이스 키 입력(페어링).
4. 회의 시작 → (원격 시청자용) 서버 콘솔에서 **Go live (public)** → QR 공유.

> 각 OS 경고 통과는 **앱마다 한 번**만 하면 됩니다(같은 앱을 재설치하지 않는 한 반복되지 않음).

## 1. macOS (가장 주의가 필요한 경로)

배포물: `.dmg` (Apple Silicon/Intel). 빌드시 **ad-hoc 서명**(`codesign -s -`, 무료·Apple 계정 불필요)이 적용되어 Apple Silicon의 최악 시나리오인 *"앱이 손상되었으며 열 수 없습니다"* 를 대부분 회피합니다.

### 1.1 설치
1. `.dmg`를 더블클릭 → 열린 창에서 앱 아이콘을 **Applications** 폴더로 드래그.

### 1.2 첫 실행 (Gatekeeper 통과)
1. **응용 프로그램**에서 앱을 더블클릭.
2. *"개발자를 확인할 수 없기 때문에 열 수 없습니다"* 경고가 뜨면 **취소**(Cancel)를 누릅니다. ← 여기서 "휴지통으로 이동"을 누르지 마세요.
3. **시스템 설정**(System Settings) → **개인정보 보호 및 보안**(Privacy & Security)을 엽니다.
4. 아래로 스크롤하면 *"'앱이름'이(가) 확인되지 않은 개발자의 것이기 때문에 차단되었습니다"* 메시지와 **"그래도 열기"**(Open Anyway) 버튼이 보입니다 → 클릭.
5. 다시 뜨는 확인 창에서 **"열기"**(Open) → Touch ID/암호로 확인.
6. 이후부터는 일반 앱처럼 더블클릭으로 열립니다.

> 📸 _스크린샷 자리_: `docs/install-img/macos-open-anyway.png` (4번 단계의 Privacy & Security 패널 — **실제 macOS에서 캡처 필요**)

### 1.3 최후의 수단 — "손상되었다"가 계속 뜰 때
일부 환경(특정 다운로드 경로/격리 속성)에서는 ad-hoc 서명에도 "손상" 경고가 남을 수 있습니다. 이때만 터미널에서 격리 속성을 제거합니다(앱 이름을 실제 이름으로 바꾸세요):

```bash
xattr -dr com.apple.quarantine "/Applications/yeson-server-console.app"
```

> ⚠️ 이 명령에 **의존하지 마세요** — 일반 사용자에게 터미널은 마지막 수단입니다. 1.2 경로가 정상 절차입니다. 이 경고가 반복적으로 다수 사용자에게 발생하면 **Apple 공증**(P9)으로 전환해야 한다는 신호입니다.

## 2. Windows (가장 쉬운 경로)

배포물: `.msi` 또는 NSIS `.exe` 설치 관리자(미서명).

### 2.1 설치
1. 설치 관리자를 더블클릭.
2. **Microsoft Defender SmartScreen**이 *"Windows에서 PC를 보호했습니다"*(Windows protected your PC) 창을 띄웁니다.
3. **"추가 정보"**(More info)를 클릭 → 하단에 **"실행"**(Run anyway) 버튼이 나타납니다 → 클릭.
4. 설치 마법사를 따라 완료.

> 📸 _스크린샷 자리_: `docs/install-img/windows-smartscreen-runanyway.png` (3번 단계 — **실제 Windows에서 캡처 필요**)

> SmartScreen 경고는 다운로드 평판이 쌓이지 않은 미서명 설치 관리자에서 정상입니다. "추가 정보 → 실행"이 세 OS 중 가장 간단한 통과 절차입니다.

---

## 3. Linux

배포물: `.AppImage`(이식성 우선) 또는 `.deb`(Debian/Ubuntu). 서명 경고 벽 없음.

### 3.1 AppImage
```bash
chmod +x yeson-server-console_*.AppImage
./yeson-server-console_*.AppImage
```
또는 파일 관리자에서 **속성 → 권한 → "프로그램으로 실행 허용"** 체크 후 더블클릭.

### 3.2 .deb
```bash
sudo apt install ./yeson-server-console_*.deb
```

## 4. 설치 후 첫 구성

### 4.1 서버 콘솔
1. 앱 실행 → **운영자 계정**(이메일+비밀번호) 생성(첫 실행 1회, 로컬에서만 처리·외부 노출 없음).
2. **Gemini API 키**와 Google STT/Translate 설정을 **Config** 패널에 입력(사용자 본인 키).
3. **Start** → 서버가 `0.0.0.0:8000`에서 LAN에 노출됩니다.
4. **디바이스 키 발급** UI로 클라이언트용 키를 만듭니다.

### 4.2 클라이언트
1. 앱 실행 → 서버 주소(`ws://<서버 LAN IP>:8000`)와 디바이스 키 입력.
2. 회의 오디오 권한 허용(macOS: 화면 기록 권한) 후 회의 시작.

### 4.3 (선택) 원격 시청자
- 서버 콘솔에서 **Go live (public)** → cloudflared 공개 터널 URL 생성 → 회의별 **QR** 공유.
- 공개 터널이 끊기면 콘솔에 **저하 배너**가 뜨고, 같은 LAN 시청자는 영향받지 않습니다(P4.2).

## 5. 서명 인증서가 필요 없음 (P9′.4)

이 배포는 **Apple/Windows 서명 인증서 없이** 빌드됩니다:
- macOS: Tauri 로컬 빌드의 **ad-hoc 서명**만 사용(Apple Developer 계정 불필요).
- Windows: 설치 관리자는 **미서명**(Authenticode 인증서 불필요) — SmartScreen 안내로 통과.
- Linux: 서명 개념 없음.

`apps/server_desktop/src-tauri/tauri.conf.json`에 `signingIdentity`(macOS)나 인증서 지문(Windows) 설정이 **없으므로**, CI/로컬 모두 인증서 없이 미서명 산출물을 만듭니다.

**자동 업데이트는 그대로 동작:** Tauri 업데이터는 OS 코드서명과 **무관한 자체 minisign 서명**을 업데이트 아티팩트에 사용하므로(P8), 미서명 배포에서도 자동 업데이트가 작동합니다.

---

## 6. 정직한 한계

macOS 미서명 경로가 비기술 사용자에게 **가장 거칩니다**(설정 → "그래도 열기"가 직관적이지 않고, 일부 환경에서 "손상" 경고가 남을 수 있음). 이 가이드가 마찰을 줄이지만 없애지는 못합니다 — **규모가 커지면 Apple 공증이 유일한 진짜 해결책**입니다(P9를 미래 업그레이드로 보존).
